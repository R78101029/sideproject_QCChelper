# QCC Helper — 需求規格書

## 1. 產品概述

**QCC Helper** 是一套協助醫院同仁執行品管圈（Quality Control Circle）活動的 Web 工具。同仁可依照品管圈十大步驟，逐步填寫表單、上傳數據、透過 AI Agent 協助分析，最終產出符合醫院繳交要求的成果報告。

## 2. 目標使用者與角色

| 角色 | 說明 | 權限範圍 |
|------|------|----------|
| 圈隊代表 | 各科室品管圈圈長或指定代表，負責填寫與管理該圈專案 | 建立/編輯/檢視自己圈的專案、上傳檔案、使用 AI Agent、匯出報告 |
| 品管圈管理員 | 品管中心輔導員或管理者，負責審核與指導所有圈隊 | 檢視/評論所有專案、審核步驟成果、管理圈隊帳號、檢視統計報表 |
| 網管（系統管理員） | 資訊部門人員，負責系統維護與帳號管理 | 所有權限、帳號 CRUD、系統設定、資料備份、API 金鑰管理 |

## 3. 核心功能需求

### 3.1 專案管理

| 功能 | 說明 |
|------|------|
| 建立專案 | 輸入圈名、科別、活動期間，建立新的 QCC 專案 |
| 專案列表 | 查看所有進行中/已完成的 QCC 專案 |
| 進度總覽 | 顯示目前所在步驟、各步驟完成狀態 |

### 3.2 十大步驟 — 各步驟表單欄位與上傳需求

---

#### 步驟一：組圈

**表單欄位：**
- 圈名
- 圈徽（圖片上傳）
- 圈的意義說明
- 科別 / 單位
- 活動期間（起迄日期）
- 圈長姓名、職稱
- 輔導員姓名、職稱
- 圈員名單（姓名、職稱、角色分工）

**上傳區：**
- 圈徽圖片（PNG/JPG）

**AI Agent 協助：**
- 依科別與主題建議圈名
- 產生圈的意義說明草稿

**成果物：** 組圈登記表

---

#### 步驟二：主題選定

**表單欄位：**
- 候選主題清單（至少 3 個主題，含簡述）
- 評價項目（預設：上級政策、重要性、迫切性、圈能力、可行性，可自訂）
- 評價矩陣（每位圈員對每個主題 × 每個評價項目打分，5/3/1 分制）
- 選定主題名稱
- 選題理由（文字說明）
- 衡量指標定義（如：跌倒次數、等候時間等）

**上傳區：**
- 相關佐證資料（PDF/圖片，如：異常事件統計、投訴紀錄）

**AI Agent 協助：**
- 依候選主題產生選題理由草稿
- 自動計算評價矩陣加總與排序
- 建議衡量指標

**成果物：** 主題選定評價表、選題理由書

---

#### 步驟三：活動計畫擬定

**表單欄位：**
- 各步驟預計起迄日期
- 各步驟負責人
- 開會頻率
- 預計活動總週數

**AI Agent 協助：**
- 依總週數自動建議各步驟時程分配（建議比例）：
  - 步驟 1~6（P 階段）：佔 30%
  - 步驟 7（D 階段）：佔 30%
  - 步驟 8~9（C 階段）：佔 20%
  - 步驟 10（A 階段）：佔 10~20%
- 產生甘特圖（虛線＝預定進度、實線＝實際進度）
- 注意：「解析」與「對策擬定」不可重疊；「效果確認」與「標準化」不可重疊

**成果物：** 甘特圖、活動計畫書

---

#### 步驟四：現況把握

**表單欄位：**
- 查檢期間（起迄日期）
- 查檢項目名稱清單（即缺失類別，如：未洗手、未確認身份...）
- 查檢總數（分母）

**上傳區：**
- 原始查檢數據（CSV/Excel 檔案）
  - 格式：每列一筆紀錄，欄位包含日期、缺失類別、次數等
- 或手動輸入查檢表數據（表格介面）

**AI Agent 協助：**
- 解析上傳的 CSV/Excel，自動辨識缺失類別與次數
- 自動繪製**改善前柏拉圖**（Pareto Chart）
  - X 軸：缺失類別（依次數由高到低排列）
  - 左 Y 軸：次數
  - 右 Y 軸：累積百分比
  - 標示 80% 線
- 計算各項目佔比與累積百分比，格式如下：

  | 缺失類別 | 次數 | 累計次數 | 百分比 | 累積百分比 |
  |---------|------|---------|--------|-----------|
  | 問題 A  | 45   | 45      | 37.5%  | 37.5%     |
  | 問題 B  | 30   | 75      | 25.0%  | 62.5%     |
  | 問題 C  | 20   | 95      | 16.7%  | 79.2%     |
  | 其他    | 25   | 120     | 20.8%  | 100.0%    |

  - 項目由大到小排列，「其他」放最末
  - 項目數控制在 6~10 個以內
- 找出關鍵少數（vital few）項目（80% 線以內）
- 計算現狀值：不良次數 / 總調查次數 × 100%
- 產生現況描述文字

**成果物：** 查檢表、改善前柏拉圖、現況描述

---

#### 步驟五：目標設定

**表單欄位：**
- 現狀值（自動帶入步驟四數據：不良次數 / 總調查次數 × 100%）
- 改善重點佔比（自動帶入：柏拉圖 80% 線以內的累積百分比）
- 圈能力值（全體圈員自評，0~1 之間）
- 目標計算方式選擇：
  - 自訂目標（手動輸入）
  - 依公式計算：
    - **降低類主題**：`目標值 = 現狀值 −（現狀值 × 改善重點 × 圈能力）`
    - **提升類主題**：`目標值 = 現狀值 +（(1 − 現狀值) × 改善重點 × 圈能力）`
- 計算後目標值（自動計算或手動輸入）
- 目標設定理由（文字說明）

**AI Agent 協助：**
- 自動帶入現狀值與改善重點佔比
- 依公式計算建議目標值
- 產生目標設定說明文字（含計算過程）

**成果物：** 目標設定表（含公式計算過程）

---

#### 步驟六：解析

**表單欄位：**
- 魚骨圖主題（即要分析的問題，如「跌倒率偏高」）
- 大要因分類（預設 4M1E：人 Man、機 Machine、料 Material、法 Method、環 Environment，可自訂）
- 每個大要因下的中要因（文字輸入）
- 每個中要因下的小要因（文字輸入）
- 真因圈選（勾選哪些小要因為真因）
- 真因驗證表：
  - 小要因名稱
  - 驗證方法（文字）
  - 驗證結果（是/否為真因）
  - 佐證說明

**上傳區：**
- 真因驗證佐證資料（圖片/PDF/數據）

**AI Agent 協助：**
- 依主題建議魚骨圖各層要因
- 自動繪製魚骨圖（Fishbone Diagram）
- 建議真因驗證方法

**成果物：** 魚骨圖（特性要因圖）、真因驗證表

---

#### 步驟七：對策擬定

**表單欄位：**
- 對策清單（針對每個真因，5W1H 格式）：
  - 真因（自動帶入步驟六）
  - What：對策方案內容
  - Why：為何採此對策
  - Who：負責人
  - Where：實施地點/範圍
  - When：預計完成日
  - How：具體執行方法
- 對策評價矩陣：
  - 評價項目（預設：可行性、經濟性、效益性，可自訂）
  - 評分（5/3/1 分制，每位圈員打分）
- 採行對策標準（總分門檻）
- 採行/不採行判定

**AI Agent 協助：**
- 依真因建議對策方案
- 自動計算對策評分與排序
- 產生對策擬定說明

**成果物：** 對策擬定一覽表、對策評價表

---

#### 步驟八：對策實施與檢討

**表單欄位：**
- 每項採行對策的實施紀錄：
  - 對策名稱（自動帶入）
  - 實施日期
  - 實施前狀況描述
  - 實施後狀況描述
  - 負責人
  - 實施狀態（進行中/已完成/延遲）
  - 單項對策效果驗證（有效/無效/需修正）
  - 檢討說明

**上傳區：**
- 實施前後對比照片
- 相關文件（如：新版 SOP、教育訓練紀錄、公告等）
- 各對策的效果驗證查檢表數據

**AI Agent 協助：**
- 追蹤進度、提醒逾期項目
- 協助撰寫檢討說明

**成果物：** 對策實施檢討表

---

#### 步驟九：效果確認

**表單欄位：**
- 改善後查檢期間
- 改善後查檢總數（分母）

**上傳區：**
- 改善後查檢數據（CSV/Excel，格式同步驟四）
- 或手動輸入改善後數據

**AI Agent 協助：**
- 解析改善後數據
- 自動繪製**改善後柏拉圖**
- 自動產生**改善前後柏拉圖對比**（兩張並排）
- 計算有形成果：
  - **改善幅度**：`(改善前 − 改善後) / 改善前 × 100%`
  - **目標達成率**：`(改善前 − 改善後) / (改善前 − 目標值) × 100%`
- 產生效果確認說明文字
- 產生**無形成果雷達圖**：
  - 評估項目（預設 6~8 項，可自訂）：QCC 手法運用、溝通能力、團隊合作、問題解決能力、品質意識、責任感、積極性、和諧度
  - 全體圈員對改善前、改善後分別自評（1~5 分）
  - 雷達圖呈現改善前（虛線）vs 改善後（實線）

**成果物：** 改善後柏拉圖、改善前後對比圖、目標達成率計算表、無形成果雷達圖

---

#### 步驟十：標準化與檢討改進

**表單欄位：**
- 標準化項目清單：
  - 對策名稱
  - 標準化內容（文字）
  - 文件編號（如 SOP 編號）
  - 負責維護人
- 檢討與改進：
  - 本次活動優點
  - 本次活動待改進事項
  - 下期活動主題建議

**上傳區：**
- 標準化文件（PDF，如新版 SOP）

**AI Agent 協助：**
- 依對策內容產生 SOP 草稿
- 產生活動檢討總結
- 建議下期活動方向

**成果物：** 標準化一覽表、SOP 草稿、檢討改進表

---

### 3.3 混合輸入模式（線上填寫 / 文件上傳）

每個步驟皆支援兩種資料輸入方式，同仁可依習慣自由選擇：

| 輸入方式 | 說明 | 適用情境 |
|----------|------|----------|
| **線上填寫** | 透過系統表單逐欄填寫，即時驗證與自動計算 | 從零開始填寫、需要系統自動計算的步驟 |
| **文件上傳** | 直接上傳已完成的文件（Word/Excel/PDF/圖片），系統擷取內容 | 已有現成資料、習慣用 Office 工具處理、跨系統轉移資料 |

**各步驟支援的上傳替代方式：**

| 步驟 | 可上傳替代的內容 | 系統處理方式 |
|------|-----------------|-------------|
| 1 組圈 | 組圈登記表（Word/PDF）、圈員名冊（Excel） | AI 擷取圈名、圈員資訊，自動填入欄位 |
| 2 主題選定 | 評價矩陣表（Excel）、選題理由書（Word/PDF） | AI 解析評分矩陣，自動計算排序 |
| 3 活動計畫 | 甘特圖（Excel/圖片）、計畫書（Word/PDF） | AI 辨識時程資訊，轉為系統甘特圖數據 |
| 4 現況把握 | 查檢表（Excel/CSV）、柏拉圖（圖片） | 解析數據產生柏拉圖；圖片則直接作為成果物 |
| 5 目標設定 | 目標設定表（Word/Excel/PDF） | AI 擷取現狀值、目標值等關鍵數據 |
| 6 解析 | 魚骨圖（圖片/PDF）、真因驗證表（Excel） | 圖片直接作為成果物；Excel 解析填入驗證表 |
| 7 對策擬定 | 對策一覽表（Excel/Word） | AI 解析 5W1H 欄位，填入系統表格 |
| 8 對策實施 | 實施記錄表（Word/Excel）、照片 | 解析填入實施紀錄 |
| 9 效果確認 | 改善後查檢表（Excel/CSV）、雷達圖自評表（Excel） | 解析數據產生柏拉圖與雷達圖 |
| 10 標準化 | SOP 文件（Word/PDF）、檢討報告（Word/PDF） | 直接作為成果物附件 |

**混合模式規則：**
- 同一步驟可同時使用兩種方式（例如：上傳部分欄位的 Excel，再線上補填其餘欄位）
- 上傳文件後，系統顯示 AI 擷取結果的預覽，同仁確認後才寫入
- 上傳的原始文件保留在系統中，作為佐證附件
- 線上填寫的數據優先；若上傳內容與線上填寫衝突，提示同仁選擇

### 3.4 快速工具（成果物快速產生器）

針對報告書需要的成果物，提供簡化的互動工具，讓同仁不需深入操作即可快速產出，數據自動存入系統供報告匯出時直接取用。

#### 甘特圖快速產生器（步驟三）

| 功能 | 說明 |
|------|------|
| 一鍵範本 | 輸入活動起迄日期與總週數，系統依 PDCA 建議比例自動產生排程 |
| 拖拉調整 | 在時間軸上直接拖拉調整各步驟的起迄時間 |
| 自動校驗 | 自動檢查步驟間不可重疊的規則，違規時提示 |
| 實際進度標記 | 活動進行中可隨時更新實際進度線 |

#### 評價矩陣快速計分器（步驟二、七）

| 功能 | 說明 |
|------|------|
| 快速打分介面 | 每位圈員用按鈕點選 5/3/1 分，不需逐格輸入 |
| 即時排名 | 打分後自動加總排序，即時顯示結果 |
| 匯入匯出 | 支援從 Excel 匯入已有的評分表 |

#### 魚骨圖互動編輯器（步驟六）

| 功能 | 說明 |
|------|------|
| 範本起始 | 預設 5M1E 骨架，點擊即可新增中/小要因 |
| 拖拉排列 | 要因可拖拉移動到不同大骨下 |
| 圈選標記 | 點擊小要因即可標記為「圈選真因」（紅圈標示） |

#### 柏拉圖快速產生器（步驟四、九）

| 功能 | 說明 |
|------|------|
| 簡易表格輸入 | 直接在表格中填寫「類別＋次數」，系統自動排序、計算百分比、繪圖 |
| CSV 一鍵匯入 | 上傳 CSV/Excel 後自動辨識並繪製 |
| 圖表微調 | 可調整顏色、標籤、80% 線位置等 |

#### 雷達圖自評工具（步驟九）

| 功能 | 說明 |
|------|------|
| 滑桿打分 | 各評估項目用滑桿（1~5 分）快速評分 |
| 多人彙整 | 全體圈員各自打分後，系統自動計算平均值 |
| 前後對比 | 改善前/後兩組分數自動疊加顯示 |

**數據存取原則：**
- 所有快速工具產生的數據皆以結構化 JSON 存入 Steps.data
- 匯出報告時，系統從 Steps.data 直接讀取並重新渲染圖表
- 同仁也可將快速工具產生的圖表單獨下載為 PNG/SVG

### 3.5 文獻搜尋功能

在特定步驟中提供文獻搜尋，協助同仁找到相關實證資料，加速撰寫內容。

**適用步驟與搜尋情境：**

| 步驟 | 搜尋目的 | 搜尋範圍 |
|------|---------|---------|
| 2 主題選定 | 搜尋類似 QCC 主題的案例與成效數據，作為選題佐證 | 醫院品管圈案例、醫療品質文獻 |
| 4 現況把握 | 搜尋該問題的全國/國際基準值（benchmark），作為對比參考 | 醫療品質指標、JCI/TCPI 標準、公開統計 |
| 6 解析 | 搜尋該問題的已知原因與影響因子，協助建構魚骨圖 | 醫學文獻、護理研究、品管案例 |
| 7 對策擬定 | 搜尋實證有效的介入措施，作為對策參考 | 實證醫學文獻、最佳實務指引、他院經驗 |

**功能細節：**

| 功能 | 說明 |
|------|------|
| 關鍵字搜尋 | 輸入關鍵字，搜尋網路上的公開文獻與品管案例 |
| AI 建議關鍵字 | 依當前步驟內容，AI 自動建議搜尋關鍵字 |
| 結果摘要 | 搜尋結果由 AI 整理為重點摘要，標示來源出處 |
| 引用插入 | 點擊即可將搜尋結果引用插入當前步驟的文字欄位中 |
| 參考文獻管理 | 自動收集引用的文獻，匯出時統一列在報告末尾 |

**搜尋來源（依優先順序）：**
1. 醫療品質相關資料庫與公開網站
2. 品管圈案例分享平台
3. 一般學術搜尋引擎

**注意事項：**
- 搜尋內容不包含任何病患個資或院內機密資料
- 搜尋結果僅供參考，同仁需自行判斷適用性
- 引用文獻需標明出處，系統自動產生引用格式

#### 帳號管理功能

| 功能 | 說明 |
|------|------|

### 3.7 AI Agent 通用功能

| 功能 | 說明 |
|------|------|
| 步驟引導 | 在每個步驟提供說明，告訴同仁「這步要做什麼、怎麼做」 |

| 文字生成 | 選題理由、現況描述、對策說明、檢討文字等 |

### 3.8 資料上傳規格

| 檔案類型 | 用途 | 格式要求 |
|----------|------|----------|
| CSV/Excel (.csv/.xlsx) | 查檢表數據、評價矩陣、雷達圖自評 | 須包含對應欄位 |
| Word (.docx) | 組圈登記表、選題理由、對策表、SOP 等文字內容 | AI 擷取後需確認 |
| PNG/JPG | 圈徽、實施照片、已完成的圖表截圖 | 單檔 ≤ 5MB |
| PDF | 佐證文件、SOP、已完成的報告頁面 | 單檔 ≤ 10MB |

|----------|------|

| 單步驟匯出 | 各步驟可獨立匯出為 PDF |
| 成果發表海報 | A0/A1 尺寸海報，含十步驟摘要與關鍵圖表 |

## 5. 技術架構（建議）

```
Frontend:  Next.js + TypeScript + Tailwind CSS
Backend:   Next.js API Routes

Charts:    ECharts (柏拉圖、魚骨圖、甘特圖、雷達圖)

Export:    jsPDF + pptxgenjs
```

## 6. 資料模型概要

```
User (使用者帳號)
├── id, username, password_hash, display_name, role (team_rep/qcc_admin/sys_admin)
├── email, department, created_at, last_login_at
└── UserCircles[] (帳號與圈隊的多對多關聯)
    └── user_id, project_id, member_role (圈長/圈員)

Project (專案)
├── id, name, circle_name, department, period_start, period_end, status
├── created_by (user_id), created_at
├── Members[] (圈員)
│   └── id, name, title, role (圈長/圈員/輔導員), user_id (nullable, 可綁定帳號)
├── Steps[] (步驟狀態)
│   └── id, step_number (1-10), status (not_started/in_progress/completed), data (JSON)
│       └── input_mode: "online" | "upload" | "mixed" (紀錄該步驟的輸入方式)
├── Uploads[] (上傳檔案)
│   └── id, step_number, file_name, file_type, file_path, upload_purpose (data/attachment/替代輸入), uploaded_at
├── References[] (參考文獻)
│   └── id, step_number, title, source_url, summary, citation_text, created_at
└── ChatHistory[] (Agent 對話紀錄)
    └── id, step_number, user_id, role, content, created_at
```

## 7. 頁面結構
